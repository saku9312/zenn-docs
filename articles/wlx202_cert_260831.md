企業ネットワークなどで利用される強固なWi-Fiセキュリティ「WPA2/WPA3-Enterprise (EAP-TLS)」を、Yamaha WLX202とProxmox上のLXCコンテナを使って構築する手順を解説します。

## 構成概要

今回は2つのLXCコンテナを用いて、認証局（CA）とRADIUSサーバーを分離した構成にします。

*   **コンテナ1 (Private CA)**: 証明書の発行・管理を行う（Easy-RSAを利用）
*   **コンテナ2 (RADIUS)**: WLX202からの認証要求を受け、証明書ベースで認証する（FreeRADIUSを利用）
*   **Authenticator**: Yamaha WLX202（アクセスポイント）

:::message
**なぜCAとRADIUSを分けるのか？**
プライベートCAのルート秘密鍵（Root CAの鍵）はセキュリティの要です。これが漏洩すると不正な証明書を偽造できてしまうため、RADIUSサーバーとは切り離し、CAは普段ネットワークから隔離（または停止）しておくのがベストプラクティスです。
:::

## 1. プライベートCAの構築と証明書発行（コンテナ1）

まずはCA用コンテナ（AlmaLinux10）にSSH接続し、証明書管理ツールである `easy-rsa` を導入します。

### 1-1. Easy-RSAのインストールと初期化

パッケージをインストール後、作業用ディレクトリを作成してPKI（公開鍵暗号基盤）を初期化します。

```bash
# epelリポジトリの登録
[root@saku-ca easy-rsa]# dnf install epel-release

# パッケージのインストール
[root@saku-ca easy-rsa]# dnf update
[root@saku-ca easy-rsa]# dnf install easy-rsa

# Easy-rsaバージョンの確認
[root@saku-ca easy-rsa]# ls -la /usr/share/easy-rsa/
lrwxrwxrwx 1 root root    5 Dec 15  2025 3 -> 3.2.5
lrwxrwxrwx 1 root root    5 Dec 15  2025 3.0 -> 3.2.5
drwxr-xr-x 3 root root 4096 Sep  1 14:09 3.2.5

# DNFでインストールして出来たファイルを /etc/ 以下へコピー
[root@saku-ca easy-rsa]# mkdir -p /etc/openvpn/easy-rsa
[root@saku-ca easy-rsa]# cp -r /usr/share/easy-rsa/3/* /etc/openvpn/easy-rsa/

[root@saku-ca easy-rsa]# cd /etc/openvpn/easy-rsa/

# PKIの初期化（※既存データがある場合は初期化されるので注意）
[root@saku-ca easy-rsa]# ./easyrsa init-pki

# 証明書期間の設定
[root@saku-ca easy-rsa]# cp ./pki/vars.example ./pki/vars
[root@saku-ca easy-rsa]# vi ./pki/vars

## 124行目
# 証明書の有効期限の設定 (日数)
# 例: 7300日 = 20年
set_var EASYRSA_CA_EXPIRE    7300

## 128行目
# 中間証明書の有効期限 (日数)
# 例: 7300日 = 20年
set_var EASYRSA_CERT_EXPIRE  7300

## 135行目
# CRL（証明書失効リスト）の有効期限 (日数)
# 例: 7300日 = 20年
set_var EASYRSA_CRL_DAYS       180

# ルートCAの作成
./easyrsa --vars=pki/vars build-ca
最初にパスフレーズの入力
Common Name にはサーバー名（ドメイン）を入力

# 証明書の所在確認
[root@saku-ca easy-rsa]# cd /etc/openvpn/easy-rsa/pki/
ca.crt　があればOK
```

実行すると、Root CAの秘密鍵を保護するパスフレーズと、CAの共通名（Common Name: `MyHome-CA` など）の入力が求められます。完了すると `pki/ca.crt` （ルート証明書）が生成されます。

## 2. FreeRADIUSの構築とEAP-TLS設定（コンテナ2）

RADIUS用コンテナにログインし、FreeRADIUSを構築します。

### 2-1. インストールと証明書の配置

```bash
[root@saku-radius ~]# dnf update
[root@saku-radius ~]# dnf install freeradius freeradius-utils freeradius-ldap
```

CAコンテナで作成した以下3つのファイルを、RADIUSコンテナの `/etc/raddb/certs/` にSCP等で転送・配置します。

1.  `ca.crt`
2.  `radius-server.crt`
3.  `radius-server.key`

:::message
**freeRADIUSインストール後のフォルダ構成は？**
Ubuntu・Debian系 -> /etc/freeradius/3.*/*　ユーザー名：freeradius　サービス名：freeradius
RedHat系 -> /etc/raddb/*　ユーザー名：radiusd　サービス名：radiusd
になっている気がします。（前に試したのがUbuntuでフォルダ構成が今回と違ったため）
:::

FreeRADIUSはセキュリティ上 `radiusd` ユーザーで動作するため、秘密鍵の読み取り権限を付与します。これを忘れるとサービスが起動しません。

```bash
[root@saku-radius ~]# sudo chown radiusd:radiusd /etc/raddb/certs/radius-server.key
[root@saku-radius ~]# sudo chmod 640 /etc/raddb/certs/radius-server.key
[root@saku-radius ~]# chown -R radiusd:radiusd /etc/raddb/certs/
```

### 2-2. EAP-TLSモジュールの設定

`/etc/raddb/mods-available/eap` をテキストエディタで編集し、証明書認証を有効化します。

```text:/etc/raddb/mods-available/eap
# デフォルトの認証方式をtlsに変更
# default_eap_type = md5
default_eap_type = tls

# (中略) tls-config セクションで証明  書のパスを指定
tls-config tls-common {
    private_key_file = /etc/raddb/certs/radius-server.key
    certificate_file = /etc/raddb/certs/radius-server.crt
    ca_file = /etc/raddb/certs/ca.crt
    
    # ※ private_key_password が設定されている行があればコメントアウト（#）する
    # private_key_password = whatever
}
```

### 2-3. WLX202のクライアント登録

`/etc/raddb/clients.conf` の末尾に、WLX202からのアクセスを許可する設定を追記します。

```text:/etc/raddb/clients.conf
client wlx202 {
    ipaddr = 192.168.1.50      # WLX202のIPアドレス
    secret = YourSecretKey123  # WLX202と共有するシークレットキー
    shortname = yamaha_ap
}
```

設定が完了したらサービスを再起動し、ステータスを確認します。

```bash
[root@saku-radius ~]#sudo systemctl restart radiusd
[root@saku-radius ~]#sudo systemctl status radiusd
```

`active (running)` になっていれば、RADIUSサーバーの準備は完了です。

ちなみに、起動が失敗していたり設定が不足していないか確認するには、以下のコマンドで確認します。

```bash
[root@saku-radius ~]# radiusd -X

# 末尾にエラーが表示されます。
tls: (TLS) Failed reading certificate file "/etc/raddb/certs/radius-server.crt"
```

## 3. Yamaha WLX202の設定

WLX202のWeb GUIへログインし、RADIUSサーバーとの連携を設定します。
今回は、新規に証明書認証でしか接続できないSSIDを作成する形で進めたいと思います。

1. **VAP設定（SSIDの設定）**
   * [無線設定] ＞ [VAP設定] で新規SSIDを作成。
   * **認証方式**: `WPA2-Enterprise` （環境に合わせて `WPA2/WPA3-Enterprise` も可）
   * **暗号化方式**: `AES`
   * **SSID**: `TEST-CERT`
   * **プライマリーRADIUSサーバー**: `外部のRADIUSサーバーを使用する ＆ IPアドレス指定`
   * **プライマリーRADIUSポート番号**: `1812`
   * **プライマリーRADIUSシークレット**: `YourSecretKey123（2-3で設定したものと同一）`
   * **セカンダリRADIUSサーバー**: `不要（旧サーバーがあれば、並行期間で設定するのもできる）`
   * **PMF（管理フレーム保護）**: `使用する（「管理用の通信（マネジメントフレーム）」を暗号化して保護する機能。IEEE 802.11wという規格で標準化されており、WPA3からは必須の機能）`
   * **ブロードキャストキー更新間隔**: `更新しない（同じWi-Fi（SSID）に接続しているすべての端末が共通で使っている暗号鍵を、どれくらいの頻度で新しく作り直すかを決める設定。基本1時間か1日で設定する。）`
   * **MACアドレスフィルタリング**: `全ての接続を許可する（やりたければ制限する）`

![](https://static.zenn.studio/user-upload/d9ca40dea1fa-20260905.png)


設定を保存し、WLX202本体へ設定を送信して適用します。

## 4. 端末への証明書インストールと接続

最後に対象の端末（Windows, macOS, iOS, Android等）に証明書をインストールします。

1. **ルートCA証明書 (`ca.crt`) のインポート**
   OSの「信頼されたルート証明機関」としてインストールします。
2. **クライアント証明書 (`client01.p12`) のインポート**
   エクスポート時に設定したパスワードを入力し、「個人」または「ユーザー証明書」としてインストールします。
3. **Wi-Fi接続**
   対象のSSIDに接続する際、認証方式に **EAP-TLS** （または「スマートカードやその他の証明書」）を選択し、インポートしたクライアント証明書を指定すれば接続完了です。

:::message alert
**接続に失敗する場合のトラブルシューティング**
FreeRADIUS側で以下のコマンドを実行してデバッグモードで起動し、その状態でWi-Fi接続を試行してください。

```bash
[root@saku-radius ~]#sudo systemctl stop freeradius
[root@saku-radius ~]#sudo freeradius -X
```

コンソールに大量のログが流れます。証明書のパス間違いや権限エラー、Secretキーの不一致などの具体的なエラー原因を特定しやすくなります。
:::
